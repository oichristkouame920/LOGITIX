LOGITIX v7.7.2 - A FAIRE APRES DECOMPRESSION
============================================

CAS RECOMMANDE : VOUS AVEZ DEJA UNE V7.6 QUI FONCTIONNE
---------------------------------------------------------

1) SAUVEGARDE
Exportez d'abord la base `logitix` depuis phpMyAdmin.
Gardez aussi votre ancien dossier LOGITIX jusqu'a la fin des tests.

2) NOUVEAU DOSSIER
Decompressez le package dans :
C:\wamp64\www\LOGITIX_FINAL_COMPLET_ADMIN_V7_7_2

3) COPIER UNIQUEMENT LE SECRET LOCAL
Copiez :
ANCIEN_DOSSIER\.env.local
vers :
C:\wamp64\www\LOGITIX_FINAL_COMPLET_ADMIN_V7_7_2\.env.local

Ne copiez PAS les anciens dossiers config/, admin/, client/, models/, includes/
ou l'ancien fichier SQL par-dessus la v7.7.2.

4) VERIFIER .env.local
Si votre v7.6 fonctionne deja, conservez exactement vos mots de passe MySQL
Base64 et votre cle TOTP existante. Ajoutez seulement la ligne bootstrap si elle
n'existe pas.

Configuration locale attendue :

LOGITIX_APP_ENV=development
LOGITIX_APP_URL=auto
LOGITIX_FORCE_HTTPS=false
LOGITIX_TRUST_PROXY_HTTPS=false
LOGITIX_TRUSTED_PROXY_IPS=
LOGITIX_ADMIN_REQUIRE_2FA=true
LOGITIX_ADMIN_BOOTSTRAP_ENABLED=false

LOGITIX_DB_HOST=127.0.0.1
LOGITIX_DB_PORT=3306
LOGITIX_DB_NAME=logitix
LOGITIX_DB_USER_CLIENT=logitix_client
LOGITIX_DB_PASS_CLIENT_B64=VOTRE_VALEUR_EXISTANTE
LOGITIX_DB_USER_ADMIN=logitix_admin
LOGITIX_DB_PASS_ADMIN_B64=VOTRE_VALEUR_EXISTANTE
LOGITIX_DB_REQUIRE_TLS=false
LOGITIX_DB_SSL_CA=

LOGITIX_TOTP_ENCRYPTION_KEY=VOTRE_CLE_EXISTANTE

Si votre Wamp utilise un autre port MySQL, mettez ce vrai port a la place de 3306.
NE REGENEREZ PAS la cle TOTP si vous en avez deja une.
NE PARTAGEZ PAS .env.local.

5) NE PAS REIMPORTER LE SQL COMPLET
Sur votre base existante, n'importez pas Logitix_SQL_FINAL_COMPLET.sql.
Ce SQL est uniquement pour une installation neuve.
La mise a niveau existante passe par l'assistant non destructif.

6) ACTIVER TEMPORAIREMENT L'ASSISTANT LOCAL
Dans .env.local, changez temporairement :
LOGITIX_ADMIN_BOOTSTRAP_ENABLED=true

7) OUVRIR L'ASSISTANT DANS LE NAVIGATEUR
Utilisez exactement :
http://localhost/LOGITIX_FINAL_COMPLET_ADMIN_V7_7_2/admin/bootstrap.php

L'assistant est volontairement refuse si :
- LOGITIX_APP_ENV n'est pas development ;
- LOGITIX_ADMIN_BOOTSTRAP_ENABLED n'est pas true ;
- la requete ne vient pas de 127.0.0.1 / ::1 ;
- le nom d'hote HTTP n'est pas localhost / 127.0.0.1 / ::1 ;
- le serveur MySQL DBA n'est pas local.

8) DANS LE FORMULAIRE BOOTSTRAP
Hote MySQL : 127.0.0.1
Port : votre port Wamp
Base : logitix
Utilisateur DBA : root (ou votre compte DBA local)
Mot de passe DBA : votre vrai mot de passe root local ; laissez vide uniquement
si votre root Wamp n'a effectivement aucun mot de passe.

Laissez cochee la mise a niveau v7.7.2.
Laissez l'activation admin cochee si vous avez besoin de l'admin.
Ne cochez la reinitialisation forcee que si un admin ACTIF existe deja et que
vous voulez volontairement remplacer son mot de passe et sa 2FA.

9) CONSERVER LE MOT DE PASSE ADMIN TEMPORAIRE
L'assistant affiche un mot de passe temporaire une seule fois.
Ne l'envoyez pas par message et ne le stockez pas dans le projet.

10) DESACTIVER IMMEDIATEMENT LE BOOTSTRAP
Dans .env.local, remettez :
LOGITIX_ADMIN_BOOTSTRAP_ENABLED=false

Rechargez /admin/bootstrap.php : la page doit repondre "Page introuvable.".

11) PREMIERE CONNEXION ADMIN
Ouvrez :
http://localhost/LOGITIX_FINAL_COMPLET_ADMIN_V7_7_2/admin/connexion.php

Connectez-vous avec l'email admin et le mot de passe temporaire.
LOGITIX impose ensuite le changement du mot de passe et la 2FA si elle est activee.

12) TESTS AVANT DE SUPPRIMER L'ANCIEN DOSSIER
- connexion avec un client existant ;
- creation d'un nouveau client ;
- creation d'un devis client ;
- traitement du devis dans l'admin ;
- conversion du devis en expedition ;
- affectation vehicule + chauffeur (+ remorque si besoin) ;
- passage en_cours puis verification cote client ;
- passage livree ;
- activation/desactivation d'un client ;
- reinitialisation de mot de passe client ;
- gestion vehicule/chauffeur/remorque/entrepot ;
- journal d'audit ;
- deconnexion/reconnexion admin et verification 2FA.

ERREURS LES PLUS COURANTES
---------------------------
1045 : utilisateur/mot de passe MySQL incorrect. Ne reimportez pas le SQL ;
       verifiez les deux valeurs Base64 dans .env.local par rapport aux comptes
       logitix_client@127.0.0.1 et logitix_admin@127.0.0.1.

2002 / 2003 : MySQL arrete, mauvais hote ou mauvais port.

1049 : la base logitix n'existe pas.

1142 / 1143 / 1356 : privileges/vues incomplets ; relancez le bootstrap avec la
                      mise a niveau cochee.

Secret base64 invalide : la valeur *_B64 a ete mal copiee. Conservez les signes =
                         de fin et n'ajoutez pas de guillemets.

Erreur TOTP/dechiffrement : la mauvaise LOGITIX_TOTP_ENCRYPTION_KEY a ete copiee.
                            Restaurez celle de l'ancien .env.local.

Migration bloquee sur une expedition : les donnees existantes violent une nouvelle
contrainte. Le message indique le type de conflit ; corrigez la donnee concernee,
puis relancez. La migration ne supprime pas la donnee automatiquement.

Conflit vehicule/chauffeur/remorque : la ressource est deja utilisee par une
expedition en cours. Rechargez et choisissez une ressource disponible.

"Failed loading ... xdebug" en CLI : ce probleme du PHP CLI n'empeche pas
l'assistant Web local. Utilisez /admin/bootstrap.php pour la migration/activation.

INSTALLATION NEUVE UNIQUEMENT
-----------------------------
Si aucune base LOGITIX n'existe, utilisez Logitix_SQL_FINAL_COMPLET.sql avec un
compte DBA MySQL. Le garde-fou destructif est a 0 par defaut. Ne le passez a 1
que pour une reinstallation volontaire apres sauvegarde.

AUCUNE MODIFICATION DE CODE PHP/CSS/JS N'EST NECESSAIRE APRES DECOMPRESSION.
Pour une mise a niveau d'une v7.6 fonctionnelle, la seule adaptation locale
normale est .env.local + l'execution de la migration via le bootstrap.

CORRECTIF MYSQL #3823 - V7.7.2
------------------------------
La v7.7.2 corrige le conflit MySQL entre :
- chk_expeditions_active_resources ;
- les colonnes generees active_vehicule_id / active_chauffeur_id / active_remorque_id ;
- les anciennes actions FK ON DELETE SET NULL / ON UPDATE CASCADE.

Les FK ressources utilisent maintenant ON DELETE RESTRICT / ON UPDATE RESTRICT.
Cela est compatible avec les CHECK/colonnes generees et correspond au modele
LOGITIX : une ressource referencee est archivee/desactivee, pas supprimee.

SI UN IMPORT V7.7.1 A DEJA ECHOUE AVEC #3823 :
- installation neuve / base jetable : relancez le SQL v7.7.2 complet avec le
  garde-fou destructif passe temporairement a 1, car le premier import a laisse
  une base partielle ; remettez ensuite le fichier a 0 pour les imports futurs ;
- base qui contenait des donnees utiles : ne relancez pas le SQL complet. Si vous
  aviez active le mode destructif, restaurez d'abord votre sauvegarde phpMyAdmin,
  puis utilisez /admin/bootstrap.php et la migration non destructive v7.7.2.
