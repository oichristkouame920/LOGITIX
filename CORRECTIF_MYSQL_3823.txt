LOGITIX v7.7.2 - CORRECTIF MYSQL #3823
======================================

SYMPTOME
-------
#3823 - Column 'vehicule_id' cannot be used in a check constraint
'chk_expeditions_active_resources': needed in a foreign key constraint
'fk_expeditions_vehicule' referential action.

CAUSE
-----
MySQL 8.x n'autorise pas CASCADE/SET NULL sur une colonne utilisee par un CHECK.
Il interdit aussi ces actions sur une colonne de base dont depend une colonne
STORED GENERATED. La v7.7.1 combinait ces mecanismes sur les ressources des
expeditions.

CORRECTION V7.7.2
-----------------
fk_expeditions_vehicule  : ON DELETE RESTRICT / ON UPDATE RESTRICT
fk_expeditions_chauffeur : ON DELETE RESTRICT / ON UPDATE RESTRICT
fk_expeditions_remorque  : ON DELETE RESTRICT / ON UPDATE RESTRICT

La contrainte metier et les index anti-double-affectation sont conserves.
La migration non destructive normalise automatiquement les anciennes FK avant
d'ajouter les colonnes generees et les CHECK.

QUE FAIRE APRES UNE ERREUR #3823
--------------------------------
1. Si c'etait une installation neuve et que la base ne contenait rien d'utile :
   utilisez le SQL v7.7.2. Le premier essai ayant cree une base partielle, passez
   temporairement @LOGITIX_ALLOW_DESTRUCTIVE_REINSTALL a 1, executez le fichier
   entier, puis conservez 0 dans votre copie normale.

2. Si la base contenait deja des utilisateurs/donnees utiles :
   ne relancez pas le SQL complet. Si le mode destructif avait ete active lors
   de l'echec v7.7.1, restaurez d'abord votre sauvegarde. Ensuite utilisez le
   bootstrap local v7.7.2 avec la mise a niveau non destructive.

3. Ne modifiez pas .env.local sauf pour le copier dans le nouveau dossier et
   ajouter/activer temporairement LOGITIX_ADMIN_BOOTSTRAP_ENABLED lorsque vous
   utilisez l'assistant local.
